## Contracts added

### Playback request and navigation

`PlaybackRequest` carries only source/channel identity, Live media kind, and immediate previous/next channel context. It has no raw URL, locator descriptor, credential, header, or secure-store field.

The navigation contract carries only the immediate neighbors rather than a full catalog snapshot. This keeps previous/next semantics explicit without loading a large channel list into the playback layer.

`PlaybackRequest` and `PlaybackNavigationContext` redact opaque IDs in `toString()` as a defensive measure so a wrongly supplied locator-like value is not echoed to logs by model rendering.

### Failure taxonomy

The explicit categories are:

- network unavailable — retryable
- timeout — retryable
- authentication failure — non-retryable without changed credentials/evidence
- stream unavailable — retryable
- unsupported media — non-retryable
- unknown — non-retryable conservatively

The failure object carries no free-form exception/detail string, preventing accidental propagation of sensitive URLs or provider response bodies through the core model.

### Deterministic reducer

The pure reducer models:

- idle
- loading
- playing
- paused
- failed

Events cover start, prepared, play, pause, fail, retry, and stop. Retry only transitions back to loading for categories explicitly marked retryable.

### Existing locator descriptor parser

The parser accepts only the existing versioned format generated by `PlaybackLocatorDescriptor`:

- `ownplay-locator-v1|direct|...`
- `ownplay-locator-v1|xtream-live|<streamId>`

It does not introduce a second descriptor format. Parsing uses a three-part split so a direct locator payload can contain `|` without being truncated.

The parser returns explicit failure reasons for malformed input, unsupported version, unsupported kind, and invalid payload. Failures never echo the input descriptor. Direct locator rendering is always redacted.

Secure-store retrieval, source/channel ownership verification, Xtream credential retrieval, and Xtream URL construction remain outside this commit and belong to the next secure-resolution slice.
