3. TV banner carry-over
- Historical tv_banner.png was a binary asset that the connected GitHub reader could not decode for visual/text audit.
- Removed that opaque binary resource rather than leaving an unverified branding surface.
- Android TV guidance was cross-checked before finalizing the replacement: the banner must identify the app, use the 320x180 xhdpi launch-point format, and be supplied as the application banner resource.
- Replaced the historical PNG with app/src/main/res/drawable-xhdpi/tv_banner.xml.
- The vector has a 160dp x 90dp intrinsic size at xhdpi (320x180 px), dark #080A0F background, the current purple OwnPlay logomark, and an embedded OwnPlay wordmark rendered as vector paths.
- It contains no Mobile or TV suffix text.
- TV manifest continues to reference @drawable/tv_banner.

4. Device Sync scope clarification
- Current Settings navigation has no Device Sync destination; SourceSyncState is source/playlist refresh state.
- Cross-device Device Sync / pairing is explicitly retired from current product scope and must not be treated as pending work.
- The authoritative Mobile/TV specification now records this retirement.
- No legacy sync/schema architecture was deleted or reactivated in this branding/continuity closure; dormant historical compatibility code is not an active feature or backlog item.
