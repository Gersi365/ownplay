Findings before mutation
1. Channel drag targeting selected the nearest row center rather than preferring the row physically under the pointer. With different row heights this could make the drop target jump early.
2. Channel target filtering depended on UUID-shaped channel IDs to distinguish real channel rows from other LazyColumn String keys. The UI should explicitly restrict targets to visible channel IDs instead of depending on identifier shape.
3. Channel drag feedback changed target-row layout by adding "Drop before" / "Drop after" text. That altered row height while target resolution was active and could move the target under the pointer.
4. The dragged channel row did not follow the pointer visually; only the target row changed presentation.
5. Category and channel edge scrolling happened only from individual pointer-move events. Holding the pointer at a viewport edge did not continuously scroll through a long list.
6. Category auto-scroll resolved its target from the pre-scroll layout until another pointer event occurred.

Implemented corrections

Channel target resolution
- ChannelDragTargetResolver now prefers the candidate row that physically contains pointerY.
- Nearest-center selection remains only as the gap fallback.
- The resolver accepts an optional validChannelIds set.
- LiveBrowseScreen passes the current visible channel IDs and excludes non-channel LazyColumn keys explicitly.
- The dragged channel remains excluded as its own anchor.

Channel drag interaction
- Added a visual translation for the dragged channel so it follows pointer movement.
- Auto-scroll compensation keeps the translated row under the pointer while the LazyColumn scrolls.
- Replaced layout-changing "Drop before" / "Drop after" text with a 3 dp insertion divider drawn as an overlay above/below the anchor row.
- Dragged/target rows keep stable layout geometry.
- My Order and Favorite order persistence callbacks remain unchanged.

Category drag interaction
- Added continuous edge auto-scroll while a category drag remains near the top or bottom viewport edge.
- Re-resolves the category drop target after each consumed scroll step.
- Keeps existing moving-card translation and insertion indicator behavior.
- Remote Up/Down category ordering remains unchanged.

Shared policy
- Added DragAutoScrollPolicy for deterministic top-edge / bottom-edge / safe-zone scroll direction.
- Both category and channel drag use the same edge policy.

Regression coverage
- ChannelDragTargetResolverTest now covers:
  - valid-channel filtering independent of UUID shape;
  - containing-row preference;
  - before/after placement;
  - invalid bounds;
  - null target cases.
- CategoryReorderPolicyTest now covers moving to first and last positions plus invalid-anchor stability.
- DragAutoScrollPolicyTest covers top edge, bottom edge, safe viewport, and invalid viewport.
